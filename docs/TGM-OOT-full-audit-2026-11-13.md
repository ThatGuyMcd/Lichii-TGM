# OOT Remake integration audit, 13 November 2026

This audit considers the full captured OOT candidate set, including open, draft, closed and historical proposals. A PR may contain several independent changes and experimental predecessors; its title is not proof that its whole branch is safe or equivalent. Accepted components are adapted through the patch pipeline, retaining TGM behavior.

The original inventory contains 964 PR snapshots and their production diffs. The title/body OOT candidate register contains 394 entries, after excluding context-only program-table matches. Additional later heads and actual first-parent release-tag commits are recorded separately. No commit ancestry is used as proof of behavior.

The fixed production review uses main `fc2ce2f64e9f1fab38303a2130ae2aac2910c2f8`, Fritchii nx2 `f66ea633db6058efe31a9611718019e5bd1667eb`, oot-gather-fix/v5.8.4 `4f5c53149b7e17d1c24445f68d79a83a3b2a17f9`, and all 18 captured Fritchii release tags. The later main commit `b0f024cce5d2a85e290d5ef3b9ec02dfcf58d94e` only removes a duplicate IsBuilt method; TGM already has one method and both platform builds pass.

The local component ledgers also reconcile 235 root footprints, 171 root branch/tag commits and 134 renderer branch/tag commits. These figures overlap and must not be summed as independent fixes. Classification completeness does not mean every proposed behavior is integrated.

## Final landed-source recheck, 14 November

The final compared main tip is `b55de0c1b20684e6bf7e9feb0f6f548edf35f9c7`. Its 15 new landed commits were compared against the adapted production code, including changes originally reviewed as open PRs. Fritchii's two compared tips above are unchanged.

It remains excluded. #1684's new Star Fox prepass and #1666's numeric networking resolver are outside the OOT integration scope.

The ancestry record documents these reviewed snapshots and explicit exclusions. It is not a claim that every upstream file or proposed behavior is copied. Later upstream arrivals are next-audit candidates rather than silently included in the validated source.

## Retained contracts

Forest Lantern dark/light, selected-game artwork, handheld touch targets, full-screen settings and all existing setting declarations remain. Existing data/save/keys/Eden/portable/XDG paths, Photo Mode, seven OOT aspect add-ons and guarded game patches remain. Frame generation stays off by default. Explicit shader preparation retains its pinned recipe, strong game/build/translator/GPU identity, owned worker, cancellation, locks and checkpoints.

Protected dependencies/submodules, src/dynarmic, RecompiledFuncs and RecompiledPatches are unchanged. The optional Linux FSR4 runtime is built from unchanged pinned external source and bundled with corresponding source, licenses and provenance; this does not validate rendering on AMD hardware.

## Deliberate exclusions

- Protected Dynarmic/API, SDK and DXVK dependency edits cannot be imported under the owner rules. Allowed wrapper changes are considered separately.
- Fake occlusion, unvalidated macro shortcuts, unprotected HotClean uploads, speculative GPU-byte discard and unsafe cleared-depth upload skipping lack the required correctness/lifetime proof.
- Raw trace/replay and bug-bundle shader attachments retain parser, byte-bound or captured-identity gaps. Existing bounded diagnostics remain available.
- Foreign UI/data-root migrations, enforced hardware/default revisions, automatic resolution degradation and forced OOT speed-limit overrides conflict with retained owner choices.
- Detached unbounded build workers, unsafe signal-handler stack walking and raw asynchronous pushbuffer parsing are not substituted for owned/bounded work.
- Distinct old counter sets, movie audio-clock/hold implementations and controller vendor-effect protocols are identified as alternatives, not silently credited as equivalents. Their specific gaps are in the local component ledgers.
- External PGO profiles are not interchangeable with the local compiler/training data. No emulator/game is launched for unattended profiling or validation.

## Evidence and limits

One post-cutoff addition is included: [main #1672](https://github.com/zortos293/Lichii/pull/1672), head `1c652959baaa8fc4f7db1219ff432ad8421f0b53`, bounds finite OOT DLSS color input to its declared LDR range. The effects baseline uses a separate exact-copy shader, so the comparison retains the original values. This guard does not apply to generic HDR inputs. Newer unrelated arrivals remain in the post-cutoff snapshot.

Detailed reviewed SHAs, patch hashes, per-component reasons, actual source comparisons, macro/interpreter and A64 fixtures, build/test logs, source identity, dependency checks and checksums remain under `build-local/all-oot-integration-2026-11-13` and `build-local/artifacts/checkpoints`. Raw guest fixtures and captures are private and are not shipped.

Each delivered candidate must have an exact-source Windows ZIP and Linux AppImage, all applicable CTest groups, UI/settings retention, protected-source identity, permission tests as an unprivileged user and standalone AppImage Qt launcher checks. Package manifests identify the actual tested source.

These checks do not establish native 60 FPS, a twofold rendering gain, visual correctness in every game scene or a GPU-timeout cure. The owner deferred the separate Castle Town performance investigation.
